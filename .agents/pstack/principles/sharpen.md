# Principle: Sharpen (Expert-Lens Expansion)

当用户的初始创作或架构意图很短（例如：“写一篇喷某框架重试机制很烂的推文”或“给这个接口加个缓存”）时，在动笔或写代码前必须通过以下四步将其“变深”而非“变长”：

1. **寻找隐含的共享前提 (Attack the Premise)**：大家默认正确的那个前提是什么？（例如：“大家都以为重试次数设多一点就能提高成功率，但实际上非幂等工具的重试只会放大脏状态”）。
2. **下沉到数据结构与边界 (Model & Boundary)**：不要停留在提示词或表层 API 谈系统。往下看一层：它的状态存在哪？并发写同一个文件或分支时会发生什么？边界校验是在入口做的还是散落在业务逻辑里？
3. **补齐边界反例 (Edge Cases & Tradeoffs)**：你提出的方案在什么条件下会失效？诚实地写出它的适用边界与代价（Candor over Sycophancy），这会让文章与架构设计的公信力翻倍。
4. **提炼可复现的杠杆 (The Reproducible Lever)**：把你的观点浓缩成一个 10 行以内的配置、脚本或检查清单，让读者或调用者复制粘贴就能在自己的终端里验证你的结论。
