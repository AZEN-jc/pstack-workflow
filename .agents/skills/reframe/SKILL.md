# /reframe — 专家词重构与跨邻域问题映射（只读，严禁改代码）

你处于**纯只读认知重构模式**：严禁修改任何业务源码、严禁覆写 `.agents/handoffs/active-brief.md`、严禁直接开始实现或派发 Builder 子 Agent。

## 执行步骤

1. **本地实证起手（拒绝空泛摘要）**：
   优先只读检索用户提及的文件与当前仓库真实符号（`file:line#symbol`），从用户的原始文件、代码结构和原始描述出发，而不是泛泛复述。
   若用户的描述可能对应 2-3 个本质不同的问题，先列出这 2-3 个候选问题、各自对应的核心专业术语，以及区分它们的观测信号（Sign）；随后明确说明你判断最可能是哪一个及理由，并围绕它展开后续步骤。

2. **传授 8-12 个双语专家词（按“对最终架构与实现影响度”降序排列）**：
   每个术语必须给出：
   - **双语词条**：`英文标准术语（中文直观译名）` + 一句大白话本质定义；
   - **本地映射**：精确对应用户原始描述的哪一部分（若仓库已有雏形，标注 `file:line#symbol`）；
   - **真实系统/论文锚点**：给出一个真实以该含义使用此概念的开源项目、RFC 或论文。**核验铁律**：若当前宿主具备联网读取工具，必须实际打开链接确认对方确实按此含义使用该词，无法核实的链接一律删除；若处于离线 CLI 宿主，仅写明精确的开源项目/论文/RFC 名称与模块名，严禁编造 URL；
   - **赋能指令**：有了这个词，用户可以向编码 Agent 下达什么更精准的工程要求。

3. **跨邻域迁移（2-3 个相邻工程领域）**：
   挑出 2-3 个早已用不同名字解决过同构问题的相邻领域（如编译器、数据库内核、分布式共识、控制论、事件溯源等），分别说明：
   - **可直接照搬的机制**；
   - **类比在哪个边界会失效**；
   - **值得带回当前系统的关键术语**。

4. **盲区预警**：
   点出用户完全没提、但一旦落地必然踩坑的关键约束、不变量或边界条件。

5. **专家级重写（零废话）**：
   用上述精准术语将用户的原始描述重写为一段紧凑、可直接用于工程建单的描述。末尾提示下一步二选一：
   - 继续深化：`/sharpen`
   - 直接建单：`pstack route "<重写后的描述>"`
